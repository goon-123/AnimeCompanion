# On-device Keiyoushi extensions and webtoon reader

Settings → Manga extensions accepts `https://keiyoushi.github.io` and the official repository/install-link variants. It reads the current gzip/protobuf v2 catalog; the obsolete JSON list is never used. Search, language/mature-source filters, manual installation/updates, enable/disable, removal and catalog refresh are included. Cached catalogs remain available when a refresh fails.

The runtime is bundled into the iPhone/iPad app. It interprets each downloaded APK's DEX bytecode locally using the pinned Apache-2.0 `dexvm` dependency. There is no Android device, Java process, Suwayomi server, JIT entitlement or remote source-execution service. The interpreter has explicit classic and 1.6 coroutine API paths. Swift owns HTTPS requests and filesystem writes. Package hashes are checked against the official published release inventory before execution; the APK's package/version must match the selected catalog entry. This is integrity verification over HTTPS, **not an implementation of Android APK signer verification**.

Installation enumerates the actual bytecode's sources before saving. Updating writes a new content-addressed APK and atomically replaces saved state before removing the old file. Corrupt state is preserved instead of overwritten. Cancellation, request/depth/instruction/response-size limits and fresh contexts keep source work off the UI thread. Extensions have no guest filesystem, process or environment access. HTTPS is limited to public-looking DNS names on port 443, including redirects; this is not a DNS-rebinding defense or an OS process sandbox. Each operation has its own ephemeral, credential-free URLSession; no Safari cookies or app account credentials are supplied.

## Compatibility and reader scope

This is an **experimental extension layer**, not a universal compatibility claim. Matching extension API versions establishes eligibility to try a package, not full support for every source. The manager explicitly labels this distinction. Manga provides source popular/latest/search catalogs, cover grids, combined title details/chapters, a local library and reading history, and a continuous vertical webtoon reader. Private website sessions and extension-driven JavaScript are available; downloads and AniList manga tracking are not included.

Source catalogs offer a settings gear. The installed APK's preference definitions supply native switches, lists, multi-select lists and text fields; unsupported custom controls stay disabled. Typed values are bounded, saved to a separate per-source Keychain item, and seeded into `source_<id>` before source constructors run in every fresh VM. Commands verify the selected source identity before executing. Saved settings affect image cache identity as well as browsing, chapters, pages and images. String sets use a lossless in-memory codec for newline/empty entries rather than the pinned host's newline joining. Save, Cancel and restoring defaults are explicit; unreadable/future storage is kept. Preference button actions, Android-specific change listeners, source-written state across operations and browser authentication are not implemented by this settings screen.

The reader retains source page-array order, including when a source's `Page.index` differs. Its image command keeps the original page URL/metadata while resolving an empty image URL lazily, then runs the source's `imageRequest`, headers and client/interceptors. URL fragments remain available to the source (for example, image decryption keys) and are removed only at the HTTP callback boundary. The Okio host executes interpreted `Source.read` overrides rather than exposing their untranslated backing bytes. Bounded mutable cursor segments support seek/next/close and commit byte changes back to the buffer, allowing extension-owned streaming transforms to run. Real MANGA Plus XOR tests cover multiple read chunks and a key length that does not divide the chunk size. Covers use the same image path. Classic detail/chapter calls share one VM; modern sources use their combined manga-update API. The image pipeline rejects undecodable data, isolates caches by source and installed package hash, bounds encoded/decoded caches and bitmap area, slices long strips for display, and retains only page views near the viewport. Page retries do not advance saved progress. Chapter completion requires every image to have loaded and the reader to reach the final image's bottom.

Jsoup string `select`/`selectFirst` calls support regex-valued `[attribute~=pattern]` tests rather than CSS's incompatible whitespace-word meaning. Regex tests are bounded and temporarily marked for the existing selector engine, preserving combinators, receiver scope, source DOM/node identity and image order. Markers are removed before returning to source code, including on errors. Weeb Central's owned page fixture deliberately uses an Alpine object expression and an unrelated image section; the earlier literal `x-data="scroll"` fixture masked this compatibility bug. Other less common Jsoup APIs may still need host work.

Saved reading data is versioned JSON written atomically, separate from extension installations and anime/AniList data. Identity includes extension, source and original title URL. Positions include chapter, page and a normalized position within the source image; failed saves retain the previous file. Library saves, source pins, recent sources, read states and reader appearance persist on this device.

Verification includes real legacy APK metadata and request/HTML parsing; real 1.6 APK metadata; Commit Strip 1.6.0's own catalog/detail code; Weeb Central 1.6.25's details, dated chapters, long-strip page requests and source image requests against owned HTML; MangaPill and CuuTruyen's page parsing; MANGA Plus 1.6.67's real protobuf catalog, title details, dated chapters, pages and source image headers against owned messages; the live Keiyoushi catalog. MANGA Plus previously failed at nested descriptor lookup. Shared generated/primitive/list descriptors, decoder defaults and exact buffered reads now allow those owned flows to execute. Truncated data remains an error. Byte-array serializer identity is available for protobuf type checks; general byte-array serialization and collection merge operations remain explicit unsupported operations. This is not full kotlinx.serialization coverage.

Weeb Central's earlier regression reproduces a missing `Instant.Companion` field and swallowed async task failures. The host supplies that Kotlin companion and retains task exceptions through `await`, without swallowing VM limits. Live probes found HTTP 403 responses from MangaPill/CuuTruyen and a “Site Unavailable” response from Weeb Central in this environment; the user subsequently confirmed Weeb Central working on their phone. Owned replay tests are not live compatibility certification for the other sources. Authenticated/challenged sources and less common host APIs need further runtime work. No copyrighted chapter/image fixtures or extension APKs are bundled in the production app.

The interpreter is prepared from the exact upstream revision by `scripts/prepare-manga-interpreter.py`. The build/test scripts run this automatically; run it before invoking Cargo directly in a fresh checkout. The generated checkout lives under ignored `target/patched-dexvm`, keeping Cargo's shared cache untouched. Preparation verifies the revision, complete tracked delta and each patched-source SHA-256. The reviewable `support/dexvm-core.patch` corrects primitive defaults, long shift operands, full 16-bit `instance-of` type indexes, typed native null references, native reentry depth, boxed range collections and generic string joins. Range expansion is budgeted and bounded. Tests cover larger real APKs, type indexes through 65535, boxed characters, literal escaping, null strings, reverse list iteration, offsets, 64-bit atomics, reentrant locks and catchable optional-class lookup failures.

## Shared compatibility update (build 43)

Current MangaDex 1.6.0, MangaFire 1.6.34 and ManhuaUS/Madara 1.6.60 execute their actual popular-catalog code against owned API/HTML responses and return entries with covers. Earlier builds failed before their first HTTP request: wrong type indexes, missing APIs, unboxed characters, incorrect receiver arguments, and HTTP responses not implementing Closeable. These are shared host/bytecode fixes, not per-site scrapers. Native iPhone/iPad tests use the same packages and owned data. Eleven published APKs are checksum-pinned in the test downloader; production contains none.

Source HTTPS transport now preserves per-package/per-source cookies between operations and handles additional HTTP verbs. Cookies follow host/domain/path/expiry rules, are cleared on removal, never come from Safari or the app's shared cookie storage, and remain memory-only. A source's globe button opens an isolated nonpersistent WebKit profile for user-completed login/verification; Use session imports that profile's cookies and retries. A website may still reject URLSession even after verification. Embedded Android WebView execution, source-owned Android browser clients and arbitrary platform UI are **not** supplied by this sheet. Comix 1.6.54 still fails on missing Android DisplayMetrics/browser APIs; do not mark it supported or report this as universal compatibility.

For a reproducible development audit, build the cdylib and run `python3 scripts/audit-manga-extensions.py`. It downloads the current gzip/protobuf index, selects independently published packages and verifies published APK hashes. The default empty owned HTML is a pre-network/API probe, not a successful catalog assertion. `--owned-response PATH` exercises an owned parser response. `--live` performs only public catalog requests; it never downloads chapters or page images and does not certify on-device availability.

## Extension browser bridge (build 44)

Version 0.22.0 connects Android WebView loads, page callbacks, JavaScript evaluation and JavaScript interfaces to an on-device WKWebView using the same private per-package/per-source profile as the globe button. Guest callback objects remain inside the VM, including R8-renamed classes. A bounded event pump completes deferred results, schedules Handler callbacks and preserves virtual main/worker contexts; cancellation closes browser views. Browser cookie changes are reconciled against the initial native-cookie snapshot, preserving later native HTTP additions, updates and deletions instead of replacing the whole jar. Local storage reads load an empty page with the source origin, so Manga UP!'s token lookup does not fetch its website. Cubari's catalog reflects its own browser history/pins; an empty history can legitimately return no entries.

Main document and JavaScript fetch requests can invoke the APK's request interceptor and return its custom response. Browser scripts run through WebKit; no site parser or catalog response is supplied by the production host. Browser JavaScript/storage/image settings, public-host navigation, content rules, event/body bounds and isolated credentials accompany this bridge. It does not supply arbitrary Android UI, native touch simulation, Chromium boundary/reply APIs or interception of every resource/XHR request. A website may still require explicit login/verification, reject WebKit, or change its behavior.

Shared fixes also cover URI string values, WebView's ViewGroup ancestry, missing framework/functional types, empty R8-inlined Okio buffers, duration units and JSON object decoding. Object decoders visit fields by name and leave absent optional properties to the APK's generated defaults; they no longer assume every field is present in descriptor order.

The current Comix 1.6.54, Cubari 1.6.0 and Manga UP! 1.6.3 APKs return owned catalog entries with covers through their real callbacks and JSON/protobuf parsers in Rust. Thirteen test-only APKs are checksum-pinned. Native tests additionally exercise actual WebKit through the C bridge, local-storage retention/isolation, an intercepted fetch response and clearing an active profile without restoring old cookies. Resource-filter tests compile both image-policy variants with WebKit; its restricted URL-filter grammar requires separate suffix rules rather than regex alternation. Supplied documents retain their source origin via WebKit's simulated-request API. Native CI results are recorded in the follow-up PR; controlled data is not certification of live websites, logins, purchased chapters or all-extension compatibility.

## JSON, chapter metadata and HiperDex (build 45)

Version 0.23.0 fixes nullable JSON primitive/builder overloads, the JsonNull singleton and content contract, JSON element string output, JsonElement serializer dispatch, configured Json factories, and sealed JSON subtype selection/default deserializers. Float primitives keep Kotlin's shortest round-trip decimal instead of widening binary rounding errors into chapter queries. These are stable runtime APIs; no obfuscated APK class names or website parsers are patched. OkHttp query components encode reserved/Unicode data, distinguish encoded input, preserve fragments and support replacement/removal and decoded lookup.

HiperDex 1.6.89 now executes popular/latest/search and its real DTO details/chapter/page serializers against owned responses. Tests verify IDs, fractional/duplicate-number chapters, dates, ordered image URLs, null filters, source-selected content ratings, its 401/homepage retry and its browser request-header recovery callback. NamiComi 1.6.0 returns an owned entry/cover/author with a custom Json instance and sealed relationships, including its own unknown-subtype fallback. Fifteen test-only APKs are integrity-pinned.

Chapter metadata stays opaque to the host. Source-provided memo JSON and chapter numbers survive Swift encoding and are restored to a fresh SChapter before invoking the source's reader. Memo size/depth and integer fidelity are checked; malformed data fails without HTTP. Dalvik float/double comparison instructions read raw constant register bits correctly (including NaN bias), preventing a positive chapter number being ignored in favor of a numeric URL ID. The exact core patch and generated source hashes are verified; only known old generated versions are migrated, with their directories preserved.

Native regressions exercise HiperDex's actual APK and real WebKit with an owned HTML request, then verify the source retries with its captured headers. Controlled data is not certification of live access, physical-device behavior, paid content or all sources. Build 47 addresses the audited Comic Fury date-builder, Comics Kingdom reflection and Project Suki property-delegate gaps below; additional serialization configurations and full XHR/resource interception remain incomplete.

## Additional source readers (build 47)

Keep float/double arithmetic types in the DEX decoder, including normal/two-address operations and raw-constant unary conversions. Generic arithmetic must reinterpret constant register bits according to the instruction, rather than treating float/double constants as integer operands. Tests include typed/raw combinations, signed zero, infinity and NaN; the real Comics Kingdom compact reader exercises the original failure. Cache preparation accepts only exact known earlier generated states, preserves them on migration and rejects unknown edits.

Shared host APIs now include actual guest-field reflection with public/inherited access rules, Kotlin property-delegate types, regex capture-group collections (null unmatched groups, empty captures and UTF-16 ranges), sequence/Jsoup-attribute iteration, boxed UInt comparison, URI relativization and JSON Map/List interfaces with fresh JsonArray construction. Date builders retain case-insensitive parsing and optional patterns/English month names; validated Gregorian dates and explicit fixed offsets replace the old unconditional +07:00 midnight conversion. The date parser supports a bounded subset, not general Java patterns, named-zone/DST rules, or pre-epoch LocalDate.

Nineteen APKs are checksum-pinned for tests only. Comic Fury's real catalog/cover, combined details/dated chapters, ordered pages and image request pass with owned data. Comics Kingdom additionally covers compact and individual chapter settings. Project Suki covers catalog/cover, its actual POST page API, capture-based numeric sorting and images. MangaBuddy/MangaK covers catalog/cover, Next.js reader extraction and images. Project Suki/MangaK combined title updates remain outside this verified coverage. No website-specific host parser or source response is added to production.

All 80 project Rust tests pass locally. Three native Swift/C/Rust tests reuse these responses, and the retained iPhone/iPad reader suite includes source-name/error/retry coverage. Host-generated diagnostics contain only a known category and sanitized standard-library class name; raw VM exceptions stay private. The reader can open its source's existing private website session and retry after **Use session**. Native results and IPA status are tracked in `BUILD_STATUS.md`. These offline tests do not certify live website access or universal extension compatibility.

## HentaiNexus decoder compatibility (build 48)

Version 0.25.1. HentaiNexus 1.6.20's actual reader fails first because Jsoup string selectors do not understand :containsData(...), then because Kotlin `ByteArray.slice(IntRange)` is missing. Support raw script/style/comment data, case-insensitive data matching, combinators/receiver scope and `Element.data()` without treating ordinary visible text as raw data. Retain temporary-marker cleanup and node/text/instruction bounds. Byte slices return boxed signed bytes, preserve the input, accept empty ranges, reject invalid nonempty indices and bound expansion before allocation.

Twenty APKs are checksum-pinned for tests only. New owned fixtures exercise the extension's popular/latest/search, details and dated chapter, encoded page metadata, image order/transport, image-quality preferences, empty readers and malformed/missing-quality failures. The APK performs its own decoding; production gains standard host APIs, with no source-specific decoder. Two native Swift/C/Rust tests replay the same fixtures. A Linux CI job provides faster feedback alongside the retained iPhone/iPad and IPA workflows.

The catalog replay already passed on build 47's runtime; this change does not establish the cause of the device's loading spinner or certify live website availability. Authentication, website changes and other unimplemented extension APIs remain possible separate failures. Validation status is tracked in `BUILD_STATUS.md`.

## Catalog-wide compatibility audit (build 49)

Version 0.25.2 adds a separate, reproducible development audit. The frozen v2 catalog at `b00de1d361ab08eb38567ecacfd267c154130592` contains **1,444 APKs**. The build-48 baseline inventories every APK and executes **15,190 offline operation probes**, enumerating **2,221 source instances**. This is broader failure discovery, **not** 1,444 working sources.

The audit exports the actual runtime's registered APIs and parent relationships, reads bounded DEX method declarations/references, verifies published release SHA-256 values, and isolates each APK's metadata/settings/popular/latest/search/book/pages/image preflights. HTTP receives only owned empty HTML; browser calls are marked as requiring the WebKit harness. Guest filesystem/process/environment access remains denied. Processes have memory/CPU/wall-clock limits. Reports never retain request URLs, tokens, cookies, guest response strings or raw exception text.

Static unmatched references are candidates, not confirmed missing implementations: abstract methods may dispatch to guest code and shim constructors can be implicit. A successful empty-response probe only means that exercised path accepted its owned response. An unclassified failure can be a fixture limitation. None of these outcomes is live certification.

`support/compatibility-fixtures.json` links exact APK hashes and source indexes to named passing Rust tests. The report marks complete owned flow only when popular catalog, details, chapters, ordered pages and image transport all have evidence. Other stages remain partial or untested; results are never transferred across APK updates or across source languages. Settings evidence requires actual schema extraction, not merely supplying preference values to a reader. Five current-catalog source instances have complete owned-flow evidence at the baseline; older pinned APK results are retained separately as historical evidence.

The first audit identifies missing `DateTimeFormatter.ofPattern(String)` on 75 packages, an optional Android settings binding type on 119, indexed-value components on 17 and typed set arrays on 7 (overlapping packages). Build 49 adds the shared overload/type/collection contracts. Typed arrays preserve the requested component type, reuse sufficiently large arrays, null-terminate reused buffers and reject incompatible elements. Android EditText callbacks remain explicitly unsupported; loading their interface does not create Android UI. HentaiNexus now has a separate real-APK schema regression, exposing its previously untested typed-set-array path. Schema-only Android listeners/dialog labels/on-off summaries no longer overwrite default values, and EditText enabled state is preserved. These setters do not run Android UI callbacks.

HTTP request bodies now cross Rust/C/Swift as optional base64-encoded **raw bytes**, preserving binary, NUL, empty and absent bodies. UTF-8 text remains available for existing text-only fixtures and internal browser messages. Custom RequestBody serialization invokes its own content-type/writeTo methods; failures stop before HTTP. Both legacy and normal call paths, content-type precedence, malformed base64 and the existing one-megabyte body limit have dedicated regressions. This is a transport correction, not evidence that every binary-API website works.

Reports retain frozen catalog/index/release-manifest hashes, runtime revision, test-log hash, incomplete cells and version-specific evidence. Production carries no audit-only command, APK corpus or source fixture. See [BUILD_STATUS.md](../../BUILD_STATUS.md) and PR #30 for measured post-fix results.

## Build and verification

```bash
# macOS/Xcode: device arm64 plus universal arm64/x86_64 simulator XCFramework
bash scripts/build-manga-runtime.sh
# Fetch integrity-pinned APKs into ignored test storage, then run offline tests
bash scripts/test-manga-runtime.sh
swift test -j 2
xcodegen generate
```

CI builds the XCFramework once and shares it, test-only APK fixtures and license notices with native build/test jobs. The layout checks and dedicated reader checks run `MangaRuntimeTests` on both iPhone and iPad simulators, exercising the actual Swift/C/Rust bridge and a 1.6 catalog. Reader checks also verify long-strip decoding, cache isolation, invalid-image retry, covers, relaunch/resume, chapter switching and settings. The reader's UI fixtures use owned geometric artwork generated only in Debug builds. Test APKs are resources of the test bundle only. Third-party license notices are generated from Cargo's resolved dependency metadata and displayed in About → Runtime licenses.

`support/serialization-decoder.dex` contains unmodified Apache-2.0 classes from JetBrains' kotlinx.serialization 1.9.0 (AbstractDecoder, serialization kinds and protobuf annotations), filling missing host types. It does not contain website-specific logic. Rebuild with `python3 scripts/rebuild-manga-support.py` (Java 17); both input artifacts and resulting bytecode are hash-pinned. Standard Kotlin progression iteration and Java functional/map APIs are implemented in the host bridge; unsupported abstract calls fail explicitly.
